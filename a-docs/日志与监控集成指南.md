# 日志与监控集成指南 (Zap + Lumberjack + Prometheus + Grafana)

- **日志推送**: 支持直接将日志异步推送到 **Grafana Cloud Loki**，无需安装 Promtail 代理。
- **日志展示**: 支持在 Grafana 中根据服务名、环境、用户 ID 或请求 ID 快速检索日志。

## 2. 依赖库版本 (最新版)


## 3. 核心组件说明

### 3.1 Logger 初始化 (`common/logger`)
提供了 `InitLogger` 方法，可配置日志级别、保存路径、单个文件大小、备份数量等。
- 支持同时输出到控制台、本地文件和远程 **Loki**。
- 文件和 Loki 输出自动采用 JSON 格式，方便 Grafana/Loki 解析。
- 支持从环境变量读取 Loki 配置（URL, User ID, Token），实现零代码改动的环境切换。
- 默认初始化为 `zap.NewNop()` 防止空指针。

### 3.2 监控中间件 (`common/middleware/prometheus.go`)
自动记录每个接口的指标：
- `http_requests_total`: 包含 `method`, `path`, `status` 标签，用于计算 QPS 和错误率。
- `http_request_duration_seconds`: 直方图，用于分析接口耗时分布。

### 3.3 日志中间件 (`common/middleware/zap_logger.go`)
- **ZapLogger**: 记录请求的详细信息（Method, Path, Status, Latency 等）。
- **ZapRecovery**: 记录并恢复 Panic 信息，避免服务宕机。
- **ContextLogger**: 自动注入 `request_id` (从 Header `X-Request-ID` 获取) 和 `user_id`，极大方便全链路日志追踪。

## 4. 接入与业务使用示例

### 4.1 main.go 初始化步骤

```go
import (
	"common/logger"
	"common/middleware"
	"github.com/prometheus/client_golang/prometheus/promhttp"
	"github.com/gin-gonic/gin"
)

func main() {
    // 1. 初始化日志配置
    _ = logger.InitLogger(logger.Config{
        Level:      "info",                    // 日志级别
        Filename:   "./logs/app.log",          // 本地文件路径
        MaxSize:    100,                       // 100MB
        MaxBackups: 10,
        MaxAge:     30,
        Compress:   true,
        Console:    true,                      // 是否输出到控制台
        Loki: logger.LokiConfig{
            Enabled: true,
            URL:     os.Getenv("LOKI_URL"),    // 建议从环境变量读取
            UserID:  os.Getenv("LOKI_USER_ID"),
            Token:   os.Getenv("LOKI_TOKEN"),
            Labels:  map[string]string{"service": "user-service", "env": "staging"},
        },
    })

    r := gin.New()

    // 2. 注册监控与日志中间件 (注意顺序)
    r.Use(middleware.PrometheusMiddleware()) // 监控最先
    r.Use(middleware.ZapLogger())           // 之后记录日志
    r.Use(middleware.ZapRecovery())         // Panic 捕获
    
    // 假设你有 auth 中间件注入 user_id
    // r.Use(middleware.Auth()) 
    
    r.Use(middleware.ContextLogger())       // 最后注入上下文 ID (依赖 auth 获取 userID)

    // 3. 暴露指标端口给 Prometheus 抓取
    r.GET("/metrics", middleware.MetricsHandler())

    r.Run(":8080")
}
```

### 4.2 业务中使用日志
推荐通过 `logger.FromContext(c)` 获取带有 `request_id` 和 `user_id` 标签的 logger。

```go
func HandleRequest(c *gin.Context) {
    // 方式 A: 直接使用包级快捷函数 (自动使用全局 Log)
    logger.Info("用户尝试下单", 
        logger.String("item_id", "prod_123"),
        logger.Int("quantity", 2),
    )

    // 方式 B: 获取带有 request_id 和 user_id 的上下文 Logger
    ctxLogger := logger.FromContext(c)
    ctxLogger.Info("处理特定请求的日志", logger.String("status", "processing"))
}
```
> **注意**: 为了保持业务代码纯净，建议统一使用 `logger.String`, `logger.Int`, `logger.Err`, `logger.Any` 等封装好的字段方法，避免直接引用三方库 `zap`。

### 6.1 获取 Grafana Cloud 凭据
为了将日志推送到 Grafana Cloud，你需要获取以下三项信息：

1.  **URL (Endpoint)**:
    登录 [Grafana Cloud Portal](https://grafana.com/profile/org)，点击实例右侧的 **Details**，找到 **Loki** 卡片，复制 **Remote Write Endpoint**。
    *通常格式为*: `https://logs-prod-xxx.grafana.net`

2.  **User ID**:
    在同一个 Loki Details 页面中，复制 **User** 字段对应的数字 ID（如 `1441206`）。

3.  **Token (Access Policy Token)**:
    - 进入 **Security -> Access Policies**。
    - 创建一个新的 Policy，Realms 选择对应的项目名，Scopes 必须勾选 **`logs:write`**。
    - 点击 **Add Token**，复制生成的以 **`glc_`** 开头的长字符串。

### 6.2 在仪表盘查询
- **按服务名筛选**: `{service="user-service"}`
- **全链路追踪**: `{service="user-service"} | json | user_id="12345"`
- **正则匹配错误**: `{env="staging"} |= "error"`
