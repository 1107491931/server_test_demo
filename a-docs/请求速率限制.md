# Go Gin 速率限制 (Rate Limiting) 指南

本文档介绍了如何在基于 Gin 的 Go 后端项目中实现速率限制，以防止暴力请求和滥用。我们使用了 `golang.org/x/time/rate` 库来实现令牌桶 (Token Bucket) 算法。

## 简介

速率限制 (Rate Limiting) 是一种控制网络流量的技术，用于限制客户端在一定时间内可以发出的请求数量。这对于保护 API 免受 DoS 攻击、暴力破解和资源耗尽非常重要。

## 实现原理

我们封装了一个 Gin 中间件，该中间件基于 IP 地址对请求进行限制。

- **算法**: 令牌桶 (Token Bucket)
- **库**: `golang.org/x/time/rate`
- **位置**: `services/common/middleware/rate_limiter.go`

### 核心特性

1. **高性能并发**: 使用读写锁（`sync.RWMutex`）优化并发性能
2. **内存安全**: 后台协程定期清理过期客户端（默认 3 分钟未访问）
3. **优雅停止**: 支持 `Stop()` 方法，防止 goroutine 泄漏
4. **灵活配置**: 支持函数选项模式自定义配置
5. **全局单例**: 提供全局限流器，避免重复创建
6. **标准响应**: 返回标准的 HTTP 429 状态码和 Rate Limit 头部

## 使用示例

### 方式 1: 全局限流器（推荐）

使用全局单例限流器，所有路由共享同一个限流器实例，性能最优：

```go
package main

import (
    "common/middleware"
    "github.com/gin-gonic/gin"
)

func main() {
    r := gin.Default()

    // 获取全局限流器：每秒 10 个请求，突发 20 个
    globalLimiter := middleware.GetGlobalRateLimiter(10, 20)
    
    // 应用到所有路由
    r.Use(globalLimiter.Middleware())

    r.GET("/api/users", func(c *gin.Context) {
        c.JSON(200, gin.H{"message": "success"})
    })

    r.Run(":8080")
}
```

### 方式 2: 便捷函数（简单场景）

使用 `RateLimit` 便捷函数，适合快速添加限流：

```go
package main

import (
    "common/middleware"
    "github.com/gin-gonic/gin"
)

func main() {
    r := gin.Default()

    // 健康检查不限流
    r.GET("/health", func(c *gin.Context) {
        c.JSON(200, gin.H{"status": "ok"})
    })

    // API 路由组
    api := r.Group("/api/v1")
    api.Use(middleware.RateLimit(10, 20)) // 每秒 10 个请求，突发 20 个
    {
        api.GET("/users", GetAllUsers)
        api.GET("/users/:id", GetUserByID)
    }

    r.Run(":8080")
}
```

### 方式 3: 多层限流（生产环境推荐）

对不同接口应用不同的限流策略：

```go
package main

import (
    "common/middleware"
    "user-service/handler"
    "github.com/gin-gonic/gin"
)

func main() {
    r := gin.Default()

    // 健康检查不限流
    r.GET("/health", func(c *gin.Context) {
        c.JSON(200, gin.H{"status": "ok"})
    })

    // 使用全局限流器：每秒10个请求，突发20个
    globalLimiter := middleware.GetGlobalRateLimiter(10, 20)
    
    // API 路由组 - 应用全局速率限制
    v1 := r.Group("/api/v1")
    v1.Use(globalLimiter.Middleware())
    {
        users := v1.Group("/users")
        {
            // 敏感接口 - 更严格的限流：每秒 2 个请求，突发 5 个
            authGroup := users.Group("")
            authGroup.Use(middleware.RateLimit(2, 5))
            {
                authGroup.POST("/register", handler.Register) // 注册
                authGroup.POST("/login", handler.Login)       // 登录
            }

            // 查询接口 - 使用默认的全局限流
            users.GET("/:user_id", handler.GetUserByID)
            users.GET("", handler.GetAllUsers)
        }
    }

    r.Run(":8080")
}
```

### 方式 4: 自定义配置

使用函数选项模式自定义配置：

```go
package main

import (
    "common/middleware"
    "github.com/gin-gonic/gin"
    "golang.org/x/time/rate"
    "time"
)

func main() {
    r := gin.Default()

    // 创建自定义配置的限流器
    customLimiter := middleware.NewRateLimiter(
        rate.Limit(50),  // 50 QPS
        100,             // burst 100
        middleware.WithCleanupTime(5*time.Minute), // 5分钟清理一次
    )
    
    r.Use(customLimiter.Middleware())
    
    r.GET("/api/data", dataHandler)
    
    r.Run(":8080")
}
```

## API 参考

### 函数列表

#### `GetGlobalRateLimiter(qps float64, burst int) *RateLimiter`
获取全局限流器单例（推荐使用）
- `qps`: 每秒请求数
- `burst`: 最大突发请求数

#### `RateLimit(qps float64, burst int) gin.HandlerFunc`
便捷函数，返回限流中间件
- `qps`: 每秒请求数
- `burst`: 最大突发请求数

#### `NewRateLimiter(r rate.Limit, b int, opts ...RateLimiterOption) *RateLimiter`
创建新的限流器实例
- `r`: 速率限制
- `b`: 突发大小
- `opts`: 可选配置

#### `WithCleanupTime(d time.Duration) RateLimiterOption`
设置清理时间阈值（默认 3 分钟）

### RateLimiter 方法

- `Middleware() gin.HandlerFunc` - 返回 Gin 中间件
- `Allow(ip string) bool` - 检查是否允许请求
- `Stop()` - 停止清理 goroutine

## 参数说明

### qps (每秒请求数)
- `qps = 1` - 每秒 1 个请求
- `qps = 10` - 每秒 10 个请求
- `qps = 0.5` - 每 2 秒 1 个请求

### burst (突发大小)
令牌桶的容量，允许短时间内的突发流量：
- 建议设置为 `qps` 的 2-3 倍
- 过小会导致正常突发流量被拒绝
- 过大会降低限流效果

## 错误响应

当请求超过限制时，返回 `429 Too Many Requests` 状态码：

**响应头部：**
```
X-RateLimit-Limit: 10
X-RateLimit-Remaining: 0
Retry-After: 1
```

**响应体：**
```json
{
    "code": 429,
    "message": "请求过于频繁，请稍后再试",
    "retry_after": 1
}
```

## 最佳实践

### 1. 使用全局限流器

对于大部分场景，使用全局限流器单例可以：
- 减少内存占用
- 提高性能
- 统一管理限流状态

```go
globalLimiter := middleware.GetGlobalRateLimiter(10, 20)
r.Use(globalLimiter.Middleware())
```

### 2. 分层限流策略

根据接口重要性设置不同的限流策略：

| 接口类型 | 推荐配置 | 说明 |
|---------|---------|------|
| 敏感接口（登录、注册） | `RateLimit(2, 5)` | 严格限流，防止暴力破解 |
| 写入接口（创建、更新） | `RateLimit(5, 10)` | 中等限流，保护数据库 |
| 查询接口（列表、详情） | `RateLimit(10, 20)` | 宽松限流，保证用户体验 |
| 健康检查 | 不限流 | 用于监控和负载均衡 |

### 3. 合理设置清理时间

```go
// 高流量服务：更频繁清理
limiter := middleware.NewRateLimiter(
    rate.Limit(100), 200,
    middleware.WithCleanupTime(1*time.Minute),
)

// 低流量服务：延长清理间隔
limiter := middleware.NewRateLimiter(
    rate.Limit(10), 20,
    middleware.WithCleanupTime(10*time.Minute),
)
```

### 4. 监控和调整

定期监控以下指标：
- 429 错误的频率和分布
- 服务器资源使用情况
- 用户投诉和反馈

根据监控结果调整限流参数。

## 性能优化

### 读写锁优化

使用 `sync.RWMutex` 替代 `sync.Mutex`，在读多写少的场景下性能提升显著：

- **读操作**（查找已存在的 IP）：使用读锁，允许并发
- **写操作**（创建新 IP 限流器）：使用写锁，独占访问
- **双重检查**：防止并发创建重复的限流器

### 内存管理

- 后台协程定期清理过期客户端
- 默认 3 分钟未访问的 IP 会被清理
- 可通过 `WithCleanupTime` 自定义清理间隔

## 常见问题

### Q: 限流是基于什么维度的？
A: 当前实现基于客户端 IP 地址进行限流。每个 IP 都有独立的令牌桶。

### Q: 如何修改为基于用户 ID 限流？
A: 可以修改 `Middleware()` 方法，将 `c.ClientIP()` 替换为从 token 或 session 中获取的用户 ID：

```go
func (rl *RateLimiter) UserBasedMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        // 从请求中获取用户 ID
        userID := c.GetString("user_id") // 假设已通过认证中间件设置
        if userID == "" {
            userID = c.ClientIP() // 未登录用户使用 IP
        }
        
        if !rl.Allow(userID) {
            // ... 返回 429
        }
        c.Next()
    }
}
```

### Q: 多个服务实例如何共享限流状态？
A: 当前实现是单机内存限流。如果部署多个实例，每个实例的限流是独立的。要实现全局限流，需要使用 Redis 等分布式存储。

### Q: 限流器会占用多少内存？
A: 每个 IP 的限流器约占用 100 字节。假设有 10,000 个活跃 IP，约占用 1MB 内存。

### Q: 如何优雅关闭限流器？
A: 调用 `Stop()` 方法停止后台清理 goroutine：

```go
limiter := middleware.NewRateLimiter(rate.Limit(10), 20)
defer limiter.Stop() // 程序退出时清理
```

### Q: 全局限流器和路由限流器有什么区别？
A: 
- **全局限流器**：所有使用该限流器的路由共享限流状态
- **路由限流器**：每次调用 `RateLimit()` 创建独立的限流器实例

推荐使用全局限流器以获得更好的性能和统一的限流管理。
